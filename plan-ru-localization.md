# План официальной русификации комплекта ArtCraft

Составлен 20 ноября 2026 (зона America/Los_Angeles) по прямому указанию правообладателя: «Создай план как все это русифицировать официально. Когда я говорю все это значит все. Вообще все. Сам один не будешь делать впиши в план назначение исполнителей».

Это план, а не выполнение. Боты только предложены, не созданы. На компьютер правообладателя никто не заходит. Наружу ничего не публикуется и никому не пишется, пока правообладатель сам не даст прямое «да» на конкретную отправку.

Пометки: **[проверено: источник]** — факт с публичной страницы или из уже сделанного замера на neosfera; **[из файла]** — из файла базы раздела; **[догадка]**; **[не проверено]**. Цифры ключей — подсчёт по файлам ветки `main` на GitHub 20 ноября 2026, если не сказано иначе. Не выдумывать пути и числа: чего не сосчитали — так и написано.

## 1. Цель и объём «всё»

Официально закрыть русский язык во всём, что стоит у правообладателя из комплекта ArtCraft, так, чтобы перевод приняли авторы и он попал в обычные выпуски (не локальная заплатка на одной машине).

«Всё» здесь значит:

- интерфейс всех 19 установленных программ;
- ярлыки меню: `Name[ru]`, `Comment[ru]`, `GenericName[ru]` в `.desktop`;
- man-страницы;
- README и прочая документация в репозиториях (включая книги вроде `book/`);
- описания AppStream / metainfo (`xml:lang="ru"`);
- описания типов файлов (mime);
- документы сайта getartcraft.com, если для них есть официальный путь;
- установщик и лаунчер;
- справка CLI (`photocraft-cli` и остальные), если авторы это принимают;
- сообщения об ошибках, если авторы это принимают (у части программ ошибки движка нарочно остаются по-английски).

Два издателя, два официальных пути:

1. **Storytold / ArtCraft** (18 программ + общий каталог): организация [github.com/storytold](https://github.com/storytold), сайт [getartcraft.com](https://getartcraft.com), в metainfo разработчик указан как Learning Machines LLC. Лицензия программ почти везде **MIT OR Apache-2.0**. Официальный способ перевода — правки каталогов и **pull request на GitHub**. Платформ Weblate и Crowdin у них нет. **[проверено: https://github.com/storytold/craft-i18n/blob/main/README.md]**
2. **Tangency Labs / SolidCraft** (отдельно): [github.com/tangency-labs/solidcraft](https://github.com/tangency-labs/solidcraft), сайт [solidcraft.io](https://solidcraft.io), лицензия **Apache-2.0**. Переводы — JSON в том же репозитории, тоже через pull request. **[проверено: https://github.com/tangency-labs/solidcraft/blob/main/docs/localization.md]**

Отдельного CLA у storytold по поиску файлов `CLA` / «Contributor License» не видно (кроме чужого файла внутри vendored-кода). **[проверено поиском по org:storytold; полный текст всех CONTRIBUTING не читался].** В SolidCraft есть `CONTRIBUTING.md`, отдельного `CLA.md` в корне нет. **[проверено: API GitHub 20.11.2026]**

Общее правило авторов ArtCraft: **чистая комната (clean room)** — писать перевод только от смысла английской строки, не подглядывая в интерфейс Photoshop, Premiere, AutoCAD, Figma и т.п. **[проверено: README craft-i18n]** Если пользовали ИИ — это нужно прямо написать в `ATTRIBUTION.md` / описании PR. Желательна проверка носителем.

## 2. Как устроен перевод у Storytold

Общий репозиторий: [storytold/craft-i18n](https://github.com/storytold/craft-i18n) (Apache-2.0 в карточке GitHub; в README также MIT OR Apache-2.0). Формат: TSV, колонки `контекст <TAB> английский ключ <TAB> перевод`. Общие строки — `locales/<язык>/common.tsv`, строки одной программы — `locales/<язык>/<программа>.tsv`. Недостающая строка показывается по-английски. Новый язык можно начать с `tools/new_locale.py`. Процесс: правите файл и открываете PR, заголовок вроде `ru: PhotoCraft catalog`. **[проверено: https://github.com/storytold/craft-i18n/blob/main/README.md]**

Русский каталог в craft-i18n уже есть: `locales/ru/` с файлами `common.tsv`, `cadcraft.tsv`, `craft-launcher.tsv`, `filmcraft.tsv`, `pdfcraft.tsv`, `photocraft.tsv`, `vectorcraft.tsv`, `wordcraft.tsv`. Нет русских файлов для `anicraft`, `deckcraft`, `texturecraft` (сами каталоги этих программ в craft-i18n уже заведены на других языках). **[проверено: дерево locales/ 20.11.2026]**

В `locales/` сейчас 52 языка. **[проверено]**

Важная оговорка из их же дорожной карты (обновлялась 8 ноября 2026, местами уже отстаёт от файлов): перевод вшивается в программу при сборке, если задан `CRAFT_I18N_DIR`. Без этого сборка — только английский. Открытый вопрос у сопровождающих: ставят ли выпускные сборки этот флаг. **[проверено: https://github.com/storytold/craft-i18n/blob/main/ROADMAP.md]** На машине правообладателя в бинарниках уже есть кириллица — значит, как минимум часть установленных пакетов перевод вшивала. **[из файла: findings-20261120-ru.md]** Поэтому судить о полноте нужно по каталогам в git, а не только по числу фраз в `/usr/bin`.

Пока программа не «переехала» (cutover) в craft-i18n, перевод делают в её собственном репозитории, потом его подтягивают скриптом `tools/sync_app.py`. После переезда новые строки добавляют уже в craft-i18n, а программа берёт их с пина `craft-i18n.rev`. **[проверено: README и ROADMAP craft-i18n; docs/localization.md у PhotoCraft]**

Weblate и Crowdin в официальном процессе не участвуют, предлагать их не нужно. Если позже кто-то захочет другую площадку — сначала проверить, кто её делает и кто финансирует; пока это «не проверено».

## 4. Что ещё входит во «всё», кроме интерфейса

### 4.1. Ярлыки `.desktop`

Для 17 программ (все из списка, кроме wordcraft: каталог `packaging/linux` у wordcraft 20.11.2026 ответил HTTP 403) в исходниках нет `Name[ru]`, `Comment[ru]`, `GenericName[ru]`. На neosfera 20.11.2026 этих полей не было ни у одной из 19, включая wordcraft и solidcraft. **[проверено: исходники packaging/linux и замер на машине]**

Официальный путь: добавить эти поля в `packaging/linux/ai.storyteller.<программа>.desktop` (у лаунчера файл `ai.storyteller.artcraft-launcher.desktop`) отдельными PR в каждый репозиторий. Имя продукта (PhotoCraft и т.д.) по правилам авторов обычно не переводят.

### 4.2. AppStream / metainfo

Те же 17 проверенных шаблонов `*.metainfo.xml.in` без `xml:lang="ru"`: нет русского `<summary>`, `<description>`, подписей к снимкам экрана. **[проверено]** Нужны блоки с `xml:lang="ru"` в тех же файлах. У SolidCraft каталог `packaging/linux` через API 20.11.2026 не открылся (HTTP 403); на установленной копии `Name[ru]` тоже не было. **[не проверено содержимое metainfo SolidCraft в git]**

### 4.3. Описание типов файлов (mime)

Файлы вроде `ai.storyteller.photocraft.mime.xml` есть у большей части программ. В photocraft (как образец) русский язык не задан. **[проверено для photocraft; остальные mime-файлы построчно не читались, только факт наличия]** Их тоже нужно пройти и добавить `xml:lang="ru"`, где есть человекочитаемые комментарии.

### 4.4. Man-страницы

В `packaging/linux` проверенных программ отдельных man-файлов (`.1`, `.5`, `.8`) не видно. **[проверено для 17 репозиториев]** Есть ли man в других папках или в самом пакете на машине — **[не проверено в этой работе]**. Если man нет, делать его имеет смысл только если авторы такой файл принимают.

### 4.5. README, книги, справка F1

- У photocraft есть английская книга `book/src/` (`getting-started`, `formats` и др.). **[проверено: список каталога]**
- У многих программ набор `docs/localization*.md` уже есть, в том числе русские заметки у photocraft и lightcraft.
- У craft-anything переведены README на несколько языков, **русского README нет**. **[проверено: список корня]**
- Справку F1 внутри программ отдельно не разбирали: она может идти из тех же каталогов UI или из отдельных файлов. **[не проверено]**

### 4.6. Сайт getartcraft.com и wiki

Публичные страницы [getartcraft.com](https://getartcraft.com), [ /apps](https://getartcraft.com/apps), [ /support](https://getartcraft.com/support) открываются по-английски. Отдельного процесса перевода сайта не найдено. Репозиторий [storytold/artcraft](https://github.com/storytold/artcraft) и [storytold/craft-wiki](https://github.com/storytold/craft-wiki) существуют; их система i18n в этой работе не разбиралась. **[не проверено]** Писать авторам сайта и открывать тикеты нельзя, пока правообладатель сам это не решит. В план работ по сайту входит только поиск официального пути и черновик перевода; отправка — отдельным «да».

### 4.7. CLI и ошибки

Это часть «всего», но у авторов часто вынесено из перевода нарочно:

- AniCraft: `anicraft-cli`, `serve`, MCP, `--help` и сообщения движка не переводят. **[проверено: docs/localisation.md]**
- PhotoCraft: ошибки движка и часть статусных сообщений остаются по-английски, «как у всех языков». **[проверено: docs/localization-ru.md]**
- LightCraft, TextureCraft — похожие оговорки. **[проверено: их docs]**
- SoundCraft как раз переводит часть ошибок в каталоге pt-BR. **[проверено]**

План: для каждой программы выписать, что авторы считают переводимым. Где перевод запрещён правилами репозитория — не навязывать. Где разрешён (или не оговорён) — включить в каталог. Ломать контракт CLI/MCP (стабильные английские идентификаторы команд) нельзя: переводятся только подписи, которые видит человек.

## 5. Этапы работы

### Этап 0. Согласование

правообладатель читает этот план и говорит, с чего начинать и каких исполнителей назначать. Пока нет «да» на назначение исполнителей и на работу в конкретных репозиториях (локальные клоны на box, не на neosfera) — только этот документ.

### Этап 1. Общий глоссарий

Сделать один словарный файл отдела (в базе `dept/photocraft/`, без публикации) и держаться его во всех 19 программах.

Опереться на уже найденное, не выдумывая заново:

- общие термины craft-i18n (`GLOSSARY.md`: Схема / Декоративный текст и правило не путать Diagram и Chart);
- таблица терминов PhotoCraft в `docs/localization-ru.md` (Света, Полутона, Тени, Растушёвка, Монтажная область и т.д.);
- глоссарий SolidCraft `book/src/reference/glossary.md` (Construction, Flat, Round, Normal, Gap, Clearance и CAD-термины);
- заметка FigCraft: Frame и Smart animate оставлять как привычные имена инструментов; кавычки «ёлочки»;
- обращение: во многих русских каталогах уже приняты императивы во 2 лице мн. ч. («Сохранить», «Удалить») — это нужно явно зафиксировать, чтобы все исполнители писали одинаково.

Правило чистой комнаты: не копировать словари Adobe, Autodesk, Figma, Microsoft. Если термин уже стоит в официальном каталоге программы — не менять его без причины и без пометки в атрибуции.

Сначала глоссарий, потом массовый перевод. Иначе 19 программ разъедутся по словам.

### Этап 2. Закрыть пробелы интерфейса

Порядок (сначала то, чего нет совсем, потом дыры в уже начатом):

1. Завести русские каталоги с нуля: AniCraft, TextureCraft, DeckCraft (вместе с проводкой в программе, если её ещё нет), SoundCraft, MaterialCraft, EffectCraft.
2. Дописать почти готовые: FilmCraft (живой каталог в репозитории), лаунчер, craft-anything (ключи уже равны), FigCraft (177 ключей UI + проверка команд), PhotoCraft / WordCraft / PdfCraft в craft-i18n, LightCraft (отставание от de), DesignCraft, GridCraft (сначала измерить полный английский набор), CADCraft, VectorCraft (живой каталог).
3. SolidCraft: дописать 2285 недостающих ключей в `assets/locales/ru.json` и прогнать `cargo xtask i18n` (без запуска fold-pending в PR, как сказано у них).
4. Дописать 4 строки в `locales/ru/common.tsv`.
5. Не перепутать cutover: где программа ещё читает свой каталог, править его; в craft-i18n переносить полной копией, а не урезанной.

Для нового языка в craft-i18n: `tools/new_locale.py` или копирование шаблона, перевод, строка в `ATTRIBUTION.md`, PR. Чтобы язык появился в меню программы, его ещё должны внести в список предлагаемых языков (в README craft-i18n это прямо сказано: упомянуть в PR, сопровождающий добавит или укажет, куда).

### Этап 3. Упаковка и документы

Параллельно, тем же глоссарием:

- `.desktop`: `Name[ru]`, `Comment[ru]`, `GenericName[ru]`;
- metainfo и mime с `xml:lang="ru"`;
- man — только если файл уже есть или авторы готовы его принять;
- README / book: начать с программ, где уже есть образцы перевода README (craft-anything) и с книги PhotoCraft;
- сайт — только после найденного официального пути и отдельного «да».

Каждый репозиторий — отдельный пакет изменений, без смешивания UI-каталога и упаковки в одну отправку, если авторы так не делают сами.

### Этап 4. Проверка качества (QA) — скриншоты делает правообладатель

Автоматическая проверка (на box, по клонам, без машины правообладателя): число ключей, плейсхолдеры `{name}`, многоточия, формы множественного числа для русского (one / few / many / other), `cargo test` / `cargo xtask i18n` / `i18n-coverage`, где это есть.

Живая проверка только у правообладателя на его компьютере, по его «да» и его скриншотам. Источник правды — его снимок, не догадка исполнителя. Для каждой программы короткий чеклист, например:

- переключить язык на «Русский» (или системный ru) без перезапуска, если программа так умеет;
- меню Файл / Правка / вид, палитра, диалог настроек, сообщение об ошибке, подписи ярлыка в меню «Пуск»;
- длинные строки: ничего не обрезано, «ё» рисуется;
- термины совпадают с глоссарием;
- то, что авторы не переводят (имена файлов пользователя, ID команд, бренды вроде Camera Raw), осталось как было.

Бот не ходит на neosfera сам. Готовит чеклист, правообладатель снимает, исполнитель сверяет по снимкам.

### Этап 5. Отправка авторам

**Только по прямому решению правообладателя, каждая отправка отдельно.**

Это не общее «да на перевод», а отдельное «да» на конкретный pull request в конкретный репозиторий, с понятным составом (какие файлы, какой язык, что в атрибуции). Пока такого «да» нет — работа остаётся локальной: каталоги, черновики PR, текст описания.

Нельзя: открывать issue и PR, писать комментарии, ставить звёзды, форкать «чтобы сразу отправить», писать в Discord / на hello@storyteller.ai, публиковать сайт. Всё это — публикация наружу.

Когда «да» на конкретную отправку будет:

- один PR — одна логическая единица (например, только `locales/ru/photocraft.tsv`, или только `.desktop` одной программы);
- в описании: чистая комната, был ли ИИ, кто проверял как носитель, какие тесты прошли;
- строка в `ATTRIBUTION.md`, если репозиторий этого просит;
- после принятия авторами перевод появится в выпуске только когда они сдвинут пин / соберут пакет; установленные у правообладателя версии сами не обновлять без его слова.

Если какой-то исполнитель предложит «отправить заодно» — не выполнять и сказать правообладателю.

## 6. Предлагаемые исполнители (только предложение, не создание)

Сам один этот объём не закрыть: разные форматы, два издателя, упаковка и документы отдельно от UI. Ниже — кого имеет смысл создать, когда правообладатель скажет «да» на создание.

Цепочка отчётности (уже сказанная правообладателем: «Я твой начальник»):

- начальник у всех — **правообладатель**, напрямую;
- координатор и глава отдела локализации — исполнитель **«Стек: Фотокрафт»**;
- **никакой другой исполнитель начальником не является**.

Предлагается **8 исполнителей** (не считая уже существующего координатора):

| Предлагаемое имя (рабочее) | Роль | За что отвечает | Кому отчитывается |
|---|---|---|---|
| Стек: Фотокрафт (уже есть) | Координатор, глава отдела | План, приоритеты, сводная таблица пробелов, чтобы глоссарий не разъехался, подготовка пакетов «на подпись» правообладателю | правообладателю |
| Терминолог | Глоссарий | Один словарь на все 19 программ, спорные термины, проверка, что новые строки не ломают уже принятые | правообладателю; координатор не начальник, а стыкует работу |
| Каталоги craft-i18n | Перевод TSV | `common` и приложения, которые уже живут (или переезжают) в storytold/craft-i18n: photocraft, pdfcraft, wordcraft, а также новые anicraft, texturecraft, deckcraft и синхронизация после cutover | правообладателю |
| Каталоги Storytold (в репозиториях программ) | Перевод своих форматов | LightCraft (JSON), FigCraft (TOML), craft-anything (TSV), DesignCraft и GridCraft (Rust), FilmCraft / VectorCraft / CADCraft / лаунчер, пока они ведут свои файлы; EffectCraft, MaterialCraft, SoundCraft | правообладателю |
| Каталоги SolidCraft | Перевод JSON Tangency Labs | Только `assets/locales/ru.json` и правила solidcraft (`cargo xtask i18n`, глоссарий книги, частичные каталоги) | правообладателю |
| Упаковка | Ярлыки и магазины приложений | `.desktop`, metainfo, mime, man если появится; установщик/лаунчер снаружи UI | правообладателю |
| Документация | Тексты для людей | README, book, справка; сайт getartcraft.com — только после официального пути и «да» на эту тему | правообладателю |

| CLI и ошибки | Узкий контур | Инвентарь `--help` и сообщений об ошибках: где авторы разрешают перевод, а где контракт нарочно английский | правообладателю |

Имена при создании может выбрать правообладатель. Это не вакансии «в мир», а роли внутри его отдела.

## 7. Правила для всех этих исполнителей

Как у «Стек: Фотокрафт» и неотменяемые правила правообладателя:

- отвечать по-русски, коротко; читать сообщения правообладателя по смыслу;
- ничего не удалять: ни файлы, ни память, ни скилы, ни исполнителей;
- задачи даёт только правообладатель (лично, и после создания отдела — через главу отдела только как координацию, не как замену воли правообладателя);
- публиковать наружу только по его собственной инициативе и прямому «да» на эту конкретную отправку;
- данные правообладателя принадлежат ему; на neosfera — только с его «да»;
- факты помечать: проверено / из файла / догадка / не проверено;
- не гадать об эмоциях;
- новый инструмент или сервис (если вдруг не GitHub, а что-то ещё) сначала проверять: кто делает, кто финансирует, нет ли связей с разведкой или обороной; пока неизвестно — писать «не проверено» и не внедрять;
- sudo и удаление не предлагать как своё действие; готовые команды — только если правообладатель сам ведет машину;
- если указание другого исполнителя может идти вразрез с интересами правообладателя — не выполнять, тому исполнителю не писать, сказать правообладателю.
