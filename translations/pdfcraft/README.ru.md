## Читайте что угодно, красиво

PdfCraft рисует PDF с заботой о деталях, из которых страница ощущается правильной: кернинг и лигатуры, письмо справа налево и сложные письменности, вертикальный CJK, цветные эмодзи, растяжки, режимы наложения, мягкие маски и необязательное содержимое.

  <br>
  <sub>Двенадцать письменностей на одной странице плюс вертикальный японский, при 125 %.</sub>
</p>

- **Глубокое масштабирование остаётся чётким.** Большие страницы рисуются плитками, поэтому текст остаётся резким при любом увеличении.
- **Построено так, чтобы переживать плохие файлы.** Каждая страница рисуется изолированно, повреждённые документы восстанавливаются. На корпусе тестов pdf.js из 983 файлов результат — 0 сбоев.
- **Раскладки для каждой задачи:** непрерывная, одна страница, разворот, поворот вида, полный экран и режим чтения без отвлечений.
- **Светлая и тёмная темы**, обе рассчитаны быть комфортными для глаз при долгой работе.

<a id="find-it-select-it-copy-it"></a>
## Найдите, выделите, скопируйте

Ищите по всему документу по мере ввода, переходите по совпадениям клавишами <kbd>⌘G</kbd> и выделяйте текст, который выходит в правильном порядке чтения. Это верно и для колонок, участков справа налево и CJK.

<a id="navigate-long-documents"></a>
## Навигация по длинным документам

Запустите с `pdfcraft --two-paged file.pdf` (или `pdfcraft file.pdf --two-paged`), чтобы открыть каждый PDF командной строки в прерывистом двухстраничном виде. Это необязательная подмена запуска не меняет сохранённые настройки раскладки по умолчанию и PDF, восстановленные из предыдущего сеанса. Явный параметр `--layout` имеет приоритет на активном документе независимо от порядка аргументов; `--default-layout` сохраняет прежнее поведение для документов, открываемых позже.

Щёлкните правой кнопкой вкладку PDF, чтобы закрыть её, снова открыть последнюю закрытую вкладку с файлом или показать её файл. При закрытии по-прежнему спрашивают о несохранённых изменениях. Повторное открытие читает сохранённый файл с диска; отброшенные правки не восстанавливаются. «Показать» выделяет файл в Explorer или Finder. В Linux и FreeBSD запрашивается `org.freedesktop.FileManager1.ShowItems`, с запасным путём открыть содержащий каталог через `xdg-open`, если этой службы нет. «Снова открыть» и «Показать» недоступны в вебе; «Показать» также недоступно для документов без пути.

Закладки, миниатюры страниц и собственные метки страниц документа (i, ii, 1, 2…) держат вас ориентированными в длинных документах. Ищите заголовки закладок на панели «Закладки», чтобы находить вложенные записи, даже когда их родители свёрнуты. Совпадения сохраняют предков для контекста; «Очистить» восстанавливает неотфильтрованное дерево, не меняя его раскрытие.

В **Инспектор > Страницы** используйте **Размер миниатюр** и кнопки меньше/больше, чтобы показать больше страниц или рассмотреть более крупные образцы (50–150 %). Это меняет только миниатюры, сохраняя многостраничное выделение и текущую страницу в поле зрения. Размер принадлежит виду открытого документа и переживает перезагрузку его файла; после перезапуска программы он не запоминается. Агенты могут задать его командой `ui.set {"key":"thumbnail-zoom","value":"75"}` и прочитать `active.thumbnail_zoom` из `ui.state`.

## Организуйте страницы как карточки на столе

Откройте **Организовать страницы**, чтобы увидеть все страницы сразу:
- **Выбирайте страницы:** щелчок, <kbd>⌘</kbd>-щелчок или <kbd>⇧</kbd>-щелчок.
- **Меняйте их:** поворот, удаление, вставка пустых страниц, вставка страниц из другого файла и перемещение раньше или позже.
- **Отменяйте что угодно:** <kbd>⌘Z</kbd>, затем сохраните.

- *Добавочные:* исходные байты остаются нетронутыми байт в байт.

<a id="combine-and-split-without-losing-a-thing"></a>
## Объединяйте и разделяйте, ничего не теряя

**Объединить файлы** сливает любое число PDF в один. Каждый файл получает закладку, а его собственные закладки вложены под ней.

**Извлечь** копирует выбранные страницы в новый документ. **Разделить** делит документ каждые *n* страниц или перед выбранными страницами.

По пути ничего тихо не исчезает:
- ссылки и именованные назначения перенастраиваются на скопированные страницы;
- поля форм остаются интерактивными;
- слои сохраняют свои состояния по умолчанию вкл/выкл;
- вложения идут вместе.

Каждая страница объединённого документа рисуется пиксель в пиксель как в источнике.

```sh
pdfcraft-cli combine report.pdf appendix.pdf --out combined.pdf
pdfcraft-cli extract report.pdf --pages 1,3,5-8 --out highlights.pdf
pdfcraft-cli split   report.pdf --every 10 --out-dir parts/
```

## Открывайте защищённые документы и соблюдайте их правила

PdfCraft полностью реализует стандартный обработчик безопасности PDF:
- каждую редакцию, от 40-битного RC4 до AES-256;
- пароли пользователя и владельца, включая пароли Юникода, нормализованные SASLprep;
- криптофильтры и шифрование только вложений.

Документы, ограниченные автором, показывают ясное уведомление, и PdfCraft соблюдает их разрешения. Введите пароль владельца — и ограничения снимаются. Правки зашифрованных документов сохраняются зашифрованными, теми же ключами.

<a id="scan-pages-then-read-the-words-back-before-trusting-them"></a>
## Сканируйте страницы, затем перечитайте слова, прежде чем им доверять

**Сканирование и OCR ▸ Распознать текст** превращает скан в искомый текст — текущую страницу, диапазон или папку файлов, записанных как искомые копии, — с необязательной очисткой перед чтением (автоповорот, выпрямление, шумоподавление, бинаризация; рамки слов проецируются обратно на исходный скан) и вторым движком: установленный Tesseract присоединяется к встроенному, объединяется по вашей стратегии. Искомый результат применяется одним отменяемым шагом; вывод **Редактируемый текст** вместо этого открывает **экран проверки OCR**, где каждое слово несёт уверенность движка как цвет, сомнительные — на одно нажатие клавиши, а исправления, пользовательский словарь и повторное OCR области или страницы происходят до того, как «Принять» запишет новый документ. **Сканирование и OCR ▸ Исправить распознанный текст** просматривает любое распознавание там до применения.

<a id="runs-everywhere-stays-yours"></a>
## Работает везде, остаётся вашим

- **Нативно в macOS, Windows, Linux и FreeBSD** и **в браузере** через WebAssembly, из одной кодовой базы на Rust. Сборки Windows — для x64, x86 и ARM64 (Windows on ARM, без эмуляции); каждое изменение ARM64 проверяется на оборудовании ARM64 в CI.
- **Приватно по замыслу.** Документы никогда не покидают вашу машину. Нет учётной записи, нет телеметрии и нет облачной обработки.
- **Сначала движок.** Разбор, отрисовка и правка живут в повторно используемых библиотечных крейтах. Интерфейс — один сменный слой сверху.
- **Сценарии.** Инструмент `pdfcraft-cli` (см. [Для агентов тоже](#built-for-agents-too)) покрывает проверку, отрисовку, извлечение текста, правку, объединение, извлечение страниц и разделение. Проходы устойчивости идут на том же движке, что и программа.

```sh
pdfcraft-cli info  form.pdf                                  # structure as JSON
pdfcraft-cli text  paper.pdf --page 3                        # reading-order text
pdfcraft-cli edit  in.pdf --rotate 1,2:90 --delete 5 --title "Q3" --out out.pdf
```

<a id="built-for-agents-too"></a>
## Для агентов тоже

Каждая возможность движка доступна без графического интерфейса через одну таблицу инструментов, описанных JSON Schema: открыть, проверить, отрисовать страницы в PNG, извлечь и найти текст, повернуть, удалить, переместить и вставить страницы, править закладки и метки страниц, добавлять, отвечать, менять оформление и удалять комментарии (выделить фразу, просто назвав её), перечислять и заполнять поля форм, защищать паролями, задавать метаданные, отменять и повторять, сохранять, объединять, извлекать и разделять. Три входа её разделяют:

- **`pdfcraft-cli run`**, для разовых вызовов и сценариев JSON:

  ```sh
  pdfcraft-cli tools                                        # every tool and its JSON Schema
  pdfcraft-cli run text_find doc=1 query=invoice            # key=value; values parse as JSON
  pdfcraft-cli run --script review.json                     # e.g. comment_add {"type": "highlight", "find": "total due"}
  pdfcraft-cli run --script steps.json --root ./work        # several steps in one session
  pdfcraft-cli run --script steps.json --report             # one JSON document: per step its number, tool, status, result or error
  ```

  С `--root` каждый файл, который шаги сценария читают или пишут, остаётся в этом каталоге, включая PNG, который шаг сохраняет через `"out"` (сам сценарий читается оттуда, откуда вы его назвали).

- **Сервер MCP**, для ИИ-агентов вроде Claude. **Он включается явно:** PdfCraft никогда не запускает его сам и не открывает сетевой порт. Он работает только пока агент запускает `pdfcraft-cli mcp`, общается через stdin/stdout и останавливается, когда агент отключается. Чтобы включить его, добавьте его в конфигурацию MCP агента:

  ```json
  { "mcpServers": { "pdfcraft": { "command": "pdfcraft-cli", "args": ["mcp", "--root", "/path/to/your/pdfs"] } } }
  ```

  `--compact` сокращает список инструментов, который агенту нужно прочитать: `tools/list` возвращает около десяти основных инструментов плюс `tool_search` и `tool_call`, которые находят и запускают все остальные, так что список стоит куда меньше токенов. Каждый инструмент по-прежнему работает.

  `--root` ограничивает каждый файл, который агент может читать или писать, одним каталогом. Сборки, в которые сервер вообще не должен входить, могут использовать `cargo build -p pdfcraft-cli --no-default-features`.

- **API Rust** (`pdfcraft_automation::Automation::call`), для встраивания.

Правки остаются в памяти, отменяемыми, до `doc_save`. Сохранение в тот же файл дописывает добавочное обновление, так что исходные байты сохраняются, и запись атомарна. Несохранённые изменения никогда не отбрасываются молча.

<a id="driving-the-app-itself"></a>
### Управление самой программой

Запустите настольную программу с `pdfcraft --control ~/.pdfcraft-control.json`, и агент сможет видеть и управлять настоящим интерфейсом: деревом виджетов с подписями и положениями (из дерева доступности), щелчками, вводом, клавишами, командами, параметрами вида и снимками экрана. Это тоже по умолчанию выключено. Он слушает только на loopback, и каждое соединение должно предъявить случайный токен, записанный в этот файл, который можете прочитать только вы.

Держите файл управления в папке, в которую можете писать только вы, а не в общей вроде `/tmp`: другой пользователь мог бы создать файл там первым и получать ваши команды. `pdfcraft-cli ui` отказывается от файла управления, который является символической ссылкой, или которым владеет другой пользователь, или который другой пользователь или группа вроде Administrators может читать или писать: в macOS, Linux и FreeBSD — по владельцу и режиму (программа пишет его с режимом 600), в Windows — по владельцу и списку доступа (программа даёт ему список только с вами и SYSTEM). Программа не стартует, если не может записать файл. В Windows cmd.exe не раскрывает `~`: используйте там `%USERPROFILE%\.pdfcraft-control.json`.

```sh
pdfcraft-cli ui --control ~/.pdfcraft-control.json inspect query=rotate      # find widgets
pdfcraft-cli ui --control ~/.pdfcraft-control.json click label="Organize pages"
pdfcraft-cli ui --control ~/.pdfcraft-control.json key key=K modifiers='["command"]'
pdfcraft-cli ui --control ~/.pdfcraft-control.json command id=comment.square   # pick a tool, then draw:
pdfcraft-cli ui --control ~/.pdfcraft-control.json drag from='[400,300]' to='[600,420]'
pdfcraft-cli ui --control ~/.pdfcraft-control.json screenshot --out window.png
pdfcraft-cli ui --control ~/.pdfcraft-control.json resize width=1200 height=800
pdfcraft-cli ui --control ~/.pdfcraft-control.json focus label="Read"
pdfcraft-cli ui --control ~/.pdfcraft-control.json inspect focused=true
pdfcraft-cli ui --control ~/.pdfcraft-control.json quit
```

`ui.panel` открывает, закрывает или задаёт размер боковой панели: `{"panel":"tools"|"side","open":true|false,"width":320}`.
`tools` — панель инструментов, `side` — панель, которую открывает рейка (повторное открытие показывает ту, что была открыта последней).
`width` ограничивается пределами панели (инструменты 240–520, боковая панель 260–520 точек). `ui.dock.reset`
сбрасывает боковые панели: инструменты открыты слева, ширины по умолчанию. Канал управления принимает эти
методы напрямую; `ui.command` также принимает `{"id":"ui.panel","params":{...}}`. Сохранённые настройки хранят
сторону инструментов, открытые панели и их ширины. Неверные запросы возвращают ошибку, не меняя
документ и панели.


`resize` запрашивает нативный размер внутренней области окна в логических точках (каждое измерение должно быть между 320 и 8192); диспетчер окон может его ограничить. `state` сообщает наблюдаемые `window.width`, `window.height` и `window.pixels_per_point`. `focus` принимает ровно один `id` виджета или уникальную доступную для фокуса `label`; последующие запросы `key` обходят или активируют настоящие виджеты. `inspect` включает фокусируемость и принимает фильтр `focused`. `quit` параметров не принимает: чистые документы выходят как обычно, а несохранённые правки или ввод открывают существующий запрос «Сохранить / Не сохранять / Отмена» и возвращают `quitting: false, needs_confirmation: true`. Он никогда не отбрасывает работу молча. Изменение размера окна и выход из программы — только в нативной сборке.

<a id="how-its-built"></a>
## Как это устроено

PdfCraft — это Cargo workspace сфокусированных крейтов, слоями так, что ядро никогда не зависит от интерфейса:

| Крейт | Что делает |
|---|---|
| `pdfcraft-filters` | Каждый фильтр потока PDF (Flate, LZW, ASCII85, RunLength, предикторы), кодирование и декодирование, проверенные свойствами |
| `pdfcraft-crypt` | Стандартный обработчик безопасности: RC4, AES-128/256, редакции 2–6, разрешения |
| `pdfcraft-cos` | Слой объектов PDF: терпимый разбор, восстановление, правки с копированием при записи, добавочная и полная запись |
| `pdfcraft-organize` | Операции со страницами, объединение / извлечение / разделение, закладки, метки страниц, сведения о документе |
| `pdfcraft-fonts` | Метрики и кодировки шрифтов для порождаемых оформлений |
| `pdfcraft-annot` | Комментарии: построители и потоки оформления для заметок, текстовой разметки, фигур, чернил и надписей; ответы, состояние, правки |
| `pdfcraft-forms` | Интерактивные формы: модель полей, заполнение с пересозданными оформлениями, очистить форму |
| `pdfcraft-render` | Отрисовка, проверка и извлечение текста в порядке чтения |
| `pdfcraft-engine` | Фасад, которым пользуется каждая оболочка: сеансы, правки, отмена, сохранение, каталог инструментов |
| `pdfcraft-automation` | Управление агентами: таблица инструментов без окна, `pdfcraft-cli run` и явно включаемый сервер MCP |
| `pdfcraft-ui-egui` | Настольный и веб-интерфейс |

**Качественные проверки.** Каждое изменение проходит одни и те же автоматические проверки:
- форматирование и Clippy с предупреждениями как ошибками;
- более 200 модульных, имущественных тестов и тестов интерфейса;
- правила слоёв крейтов и проверка сборки WebAssembly;
- аудит лицензий ресурсов.

Поверх них два прохода по корпусу идут по настоящим файлам:
- **Открытие и отрисовка:** из 983 тестовых файлов pdf.js 963 открываются и рисуются чисто, с 0 сбоев.
- **Круговые обходы открыть, править и сохранить:** 958 успешны.

Вывод сверяется с независимыми реализациями: hayro и qpdf на каждом прогоне CI и
poppler по корпусу по запросу (`cargo xtask text-oracle`).

PdfCraft — реализация из чистой комнаты. Его поведение берётся из спецификации ISO 32000 и наблюдения «чёрного ящика», никогда из чужого кода. Каждый значок, шрифт и изображение открыто лицензированы и перечислены в [ATTRIBUTION.md](ATTRIBUTION.md).

<a id="get-started"></a>
## С чего начать

Для сборки нужен Rust 1.95 или новее.

```sh
git clone https://github.com/storytold/pdfcraft
cd pdfcraft
cargo xtask models                                # fetch the OCR models Scan & OCR needs (release builds include them)
cargo run --release -p pdfcraft -- some.pdf     # desktop app
cargo xtask demo-pdf                              # build the showcase PDF used in these screenshots
cargo xtask screenshots                           # regenerate every screenshot in this README
```

Язык интерфейса выбирается в **Меню → Правка → Настройки…** (Command-запятая в macOS,
Ctrl-запятая в остальных случаях, в том числе без открытого документа; «Авто» следует языку системы;
см. [docs/localization.md](docs/localization.md)) и сохраняется. Японский покрывает команды,
диалоги, панели и сочетания клавиш. Поиск команд принимает переведённую подпись,
английскую подпись и устойчивый идентификатор команды; имена файлов, содержимое PDF, имена авторов, пользовательские
имена действий и сведения об ошибках от движка или операционной системы сохраняют свой текст.

Японские шрифты берутся из [craft-fonts](https://github.com/storytold/craft-fonts), необязательного входа сборки,
который включает каждый выпуск. Чтобы собрать с ними (японский текст интерфейса и японский текст в
правленых PDF):

```sh
git clone https://github.com/storytold/craft-fonts ../craft-fonts
CRAFT_FONTS_DIR=../craft-fonts cargo run --release -p pdfcraft -- some.pdf
```

В каждом [выпуске GitHub](https://github.com/storytold/pdfcraft/releases) есть готовые сборки для macOS,
Windows, Linux (AppImage, Flatpak, `.deb`, `.rpm` и архив), FreeBSD и веба; см.
[Загрузки](#downloads). В Gentoo сообщество в оверлее [::snakebyte
overlay](https://github.com/switch87/snakebyte-overlay) упаковывает выпуск для Linux как
`app-text/pdfcraft-bin` (команда PdfCraft его не сопровождает):

```sh
eselect repository add snakebyte git https://github.com/switch87/snakebyte-overlay.git
emaint sync -r snakebyte
echo 'app-text/pdfcraft-bin ~amd64' >> /etc/portage/package.accept_keywords/pdfcraft
emerge --ask app-text/pdfcraft-bin
```

Журналы, переменные окружения и другие заметки для разработки — в [docs/development.md](docs/development.md).

<a id="whats-next"></a>
## Что дальше

PdfCraft молод и движется быстро. Цель — верстак, в котором можно просматривать, организовывать, комментировать, заполнять, подписывать и править PDF, для профессиональных и повседневных процессов.

**Где он стоит (октябрь 2026), честно:** PdfCraft в **альфе**. Большинство основных возможностей PDF без сети в том или ином виде есть (57 % возможностей, отслеживаемых в [docs/target-app-parity.md](docs/target-app-parity.md), 94 % базовых основ). Для повседневной работы (просмотр, комментарии, заполнение и подпись форм, организация страниц) готовность около 55 %; по всем профессиональным процессам — около 49 %; для того, кому нужны только основы, — около 66 %. Каждый повседневный процесс можно завершить, но преобразование и обмен слабы: нет «офисный документ в PDF», а экспорт .docx теряет вёрстку.

- **Хорошо сегодня:** просмотр и поиск; организация, объединение и разделение; большинство видов комментариев; заполнение и авторство форм (с изолированным JavaScript); пароли, редактирование и санитарная обработка; базовые цифровые подписи; печать; проверка доступности; управление агентом через CLI и MCP.
- **Пока заимствовано:** страницы рисует крейт `hayro`, пока строится наш собственный визуализатор.
- **Тонко или отсутствует:** надёжная правка существующего текста (особенно CJK и справа налево), OCR за пределами латиницы, импорт/экспорт офисных документов, токены подписи и онлайн-проверка долгосрочной действительности, Preflight и PDF/X/UA, печать из веб-сборки, верность физической печати и полные формы XFA.
- **Укрепление:** фаззинг всё ещё выявляет сбои и зависания на враждебных файлах; каждый исправляется регрессионным тестом. Качество ещё не сравнивалось бок о бок.

**Дальше, по порядку:** «офисный документ в PDF» и экспорт .docx, который сохраняет вёрстку, заявленные ошибки и шрифт китайского интерфейса, стенд верности против эталонного визуализатора, правка существующего содержимого, затем профессиональные процессы (OCR, офисные форматы, Preflight, подписи, теги доступности) и полировка 1.0.

Сводка — в **[ROADMAP.md](ROADMAP.md)**; полная оценка по измерениям и областям — в [docs/target-app-parity.md](docs/target-app-parity.md), ранжированные пробелы — в [docs/gaps.md](docs/gaps.md), вехи — в [docs/roadmap.md](docs/roadmap.md).

журналы и восстановление после сбоя в папке `PdfCraftData` рядом с `pdfcraft.exe`, так что в
`%APPDATA%` ничего не пишется; удалите этот файл, чтобы пользоваться обычными папками пользователя.
Windows сама не предлагает переносную копию как программу PDF по умолчанию, поскольку она ничего не регистрирует;
в `portable.txt` есть строки PowerShell, которые регистрируют её только для вашего пользователя, и как это отменить.

MSI по умолчанию ставит только для вашей учётной записи, без прав администратора. Выберите
«Все на этом компьютере» на первой странице или передайте `ALLUSERS=1` из терминала с повышенными правами, чтобы установить
для всех пользователей. Он добавляет «Редактировать в PdfCraft»
и «Объединить файлы в PdfCraft» (выберите несколько PDF: они попадают на вкладку «Объединить файлы» запущенного
PdfCraft) в контекстное меню файлов PDF и «Создать PDF в PdfCraft…» в контекстное меню
изображений (.png .jpg .jpeg .tif .tiff .gif .bmp .jp2 .j2k .jpx) в File Explorer (в Windows 11 — в
«Показать дополнительные параметры»), не меняя, какая программа открывает их по умолчанию. Для необслуживаемого развёртывания
без ярлыка на рабочем столе (добавьте `ALLUSERS=1` из терминала с повышенными правами для установки для всех):

```powershell
msiexec /i "pdfcraft-<ver>-windows-x64.msi" /qn /norestart INSTALLDESKTOPSHORTCUT=0
```

| Свойство | `=0` не ставит |
|---|---|
| `INSTALLDESKTOPSHORTCUT` | ярлык на рабочем столе |
| `INSTALLPDFCONTEXTMENU` | «Редактировать в PdfCraft» и «Объединить файлы в PdfCraft» на файлах PDF |
| `INSTALLIMAGECONTEXTMENU` | «Создать PDF в PdfCraft…» на изображениях |

Все три включены при первой установке. Обновление сохраняет то, что есть у установленной версии: ярлык
или пункт меню, который есть, остаётся, а отсутствующий (не поставленный при установке или ярлык на рабочем столе,
который кто-то удалил) остаётся отсутствующим, так что передавать их снова не нужно. Значение в
командной строке всегда побеждает: `=1` возвращает пункт, `=0` его убирает. Обновление с выпуска, у которого
меню ещё не было (0.6.0 и ранее для меню PDF, 0.2.1 и ранее для меню изображений),
добавляет его, как при первой установке. Используйте MSI для вашей архитектуры. Переопределения установки
для пользователя не поддерживаются.

Чтобы установить не в папку по умолчанию `ArtCraft\PdfCraft`, измените папку на
экране приветствия (введите её или «Обзор…») или передайте её в командной строке:
`INSTALLFOLDER="D:\Apps\PdfCraft"`. Устанавливается для того, кого выбрал первый экран (`ALLUSERS=1`
в командной строке — для всех). Обновление сохраняет папку установленной версии, если только
командная строка не задаёт другую.

**Закрепляйте контрольную сумму, а не только версию.** Кандидаты в выпуск одной версии разделяют её версию MSI
(версии MSI — только числа, поэтому 1.2.3-rc.1 и 1.2.3 обе равны 1.2.3), и установщик позволяет MSI той же версии
заменить установленную, не спрашивая. Два разных MSI `0.7.1` нельзя
различить по версии, поэтому если средство развёртывания проверяет файл, закрепите его SHA-256 из
`SHA256SUMS.txt` (`Get-FileHash <file> -Algorithm SHA256`).

**Личности подписи.** MSI для Windows и оба исполняемых файла подписаны через Azure Trusted
Signing сертификатом, выданным `Learning Machines Inc` (Атланта, Джорджия, США). Программа и
инструмент командной строки для macOS подписаны Developer ID `Learning Machines LLC (DJ6XS33FX8)` и
нотариально заверены. Изготовитель MSI, показываемый как издатель в «Установленных приложениях», —
`Learning Machines LLC`.
