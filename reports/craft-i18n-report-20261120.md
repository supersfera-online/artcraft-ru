## 2. Правила формата TSV (кратко)

Источники: `README.md`, `docs/catalog-format.md`, `docs/adr/0001-tsv-catalogs-keyed-by-english.md`, `GLOSSARY.md`, `tools/new_locale.py`. **[из файла]**

- Каталога `locales/en/` **нет и не должно быть**: английский текст — это ключ (`Source text`). «Английский никогда не переводится, поэтому английских каталогов нет». **[из файла: docs/catalog-format.md, ADR 0001]**
- Строка данных: `context <TAB> English source text <TAB> translation` (ровно три колонки).
- Контекст обычно пустой. Слово без `@` (например `menu`, `preview`) различает омонимы. Зарезервированы только `@plural`, `@id`, `@msg`.
- Экранирование внутри колонки: только `\n`, `\t`, `\\`. Других нет.
- Плейсхолдеры `{name}` должны быть и в английском, и в переводе (порядок может отличаться). Хвост `…` (многоточие одним символом) должен совпадать.
- Пустой перевод — ошибка CI; строку лучше не включать, тогда интерфейс покажет английский.
- Ключ уникален по паре (context, source text) в одном файле.
- Строки, начинающиеся с `#`, и пустые строки игнорируются (в том числе заголовок и закомментированные заготовки).
- Каталог должен начинаться с предписанного заголовка; CI требует строку `# Clean room:`.
- `@id language.name` обязателен в каждом языке (в `common.tsv` или в каталоге приложения) — имя языка на этом языке. В `locales/ru/common.tsv` есть `@id language.name` = «Русский». **[проверено: файл]**
- `@plural`: английский источник `one|other`; перевод — формы языка через `|` в порядке CLDR. Для русского — **3** формы (`tools/plural_forms.tsv`: `ru	3	…`). **[из файла]**
- Частичные каталоги допустимы. Просмотр: `cargo test coverage_report -- --nocapture` сравнивает число строк с **самым большим** каталогом того же имени, не с объединением ключей.

### Как определяется набор ключей (эталон)

Отдельного шаблона `locales/en/` нет. **[проверено: `ls locales/en` — нет]**

- `tools/new_locale.py` берёт эталон так: «каждый `(context, source)`, который есть **хотя бы в одной** локали в файле того же имени» (объединение), минус `@id language.name` и, для файла приложения, минус ключи, уже входящие в объединение `common`. **[из файла: docstring и функция `english()` в tools/new_locale.py]**
- Штатный отчёт покрытия (`coverage()` в `crates/craft-i18n-tests/src/tree.rs`) сравнивает число строк с **максимумом по локалям** для этого имени файла, а не с объединением. Объединение может быть больше максимума, если разные локали содержат разные подмножества ключей. **[проверено: код + замер ниже]**

В этом отчёте основной эталон — **объединение ключей** (как в `new_locale.py`). Рядом указан максимум (как в `coverage_report`).

## 3. Цифры по семи программам (состояние ДО правок)

Подсчёт: собственный парсер по правилам CI (пропуск `#` и пустых строк, ключ = `(context, source)` в сыром виде колонок). Команда: `python3 /tmp/craft_i18n_audit.py`. Совпадение числа строк ru и максимумов с `cargo test coverage_report -- --nocapture` — да. **[проверено: скрипт + coverage_report]**

Расшифровка колонок:

- **Эталон (объединение)** — число уникальных ключей во всех `locales/*/«файл».tsv`.
- **Макс. локаль** — локаль с наибольшим числом строк и это число (эталон `coverage_report`).
- **Ключей в ru** — строк в `locales/ru/«файл».tsv` (файла нет — 0).
- **Нет в ru (объед.)** — ключи эталона-объединения, которых нет в ru-файле.
- **Лишних vs другие** — ключи, которые есть только в ru и ни в одной другой локали (для этих семи файлов везде 0).
- **Нет / лишние vs макс.** — относительно ключей самой полной локали.
- **Пустых** — строк с пустым переводом (CI это запрещает).
- **= en** — перевод в точности равен английскому источнику (после unescape). Не утверждается, что это ошибка: часто имена, клавиши, форматы.
- **Плейсхолдеры CI** — расхождение `{name}` или хвостового `…` (то, что ловит штатный checker).
- **Разметка `\n`** — несовпадение числа переводов строк между en и ru (штатный CI это **не** проверяет).
