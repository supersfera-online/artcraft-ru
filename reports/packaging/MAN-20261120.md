# Man-страницы photocraft / cadcraft / soundcraft / figcraft — есть ли штатный путь для ru (20.11.2026)

Отдел локализации ArtCraft (упаковка). Только локально, наружу ничего не отправлялось, ничего не удалялось. [проверено: этот заход]

Пометки: **[проверено: источник]** / **[из файла]** / **[догадка]** / **[не проверено]**.

## Итог

**Штатного пути для локализованных man-страниц нет ни у одной из четырёх программ.** Не найдены каталоги `man/ru`, `ru/man1`, `usr/share/man/ru/`, отдельный локализованный вызов `clap_mangen`, флаги языка у генератора, gettext/itstool/`.po` для man, записи в `nfpm.yaml` или в `packaging/*/package.sh`, которые ставили бы страницы в языковой подкаталог. [проверено: git ls-files и git grep по клонам `packaging/src/{photocraft,cadcraft,soundcraft,figcraft}`, ветка `l10n-ru-packaging` поверх main 20.11.2026]

Поэтому **механизм не придумывался и переводов man не писалось**; новые коммиты в ветки не делались, патчи и `STATUS.md` не менялись. [проверено]

Это согласуется с инвентарём CLI: механизма i18n у командной строки нет ни у одной программы комплекта, категория `translate` пуста, справка clap/`--help` либо прямо запрещена к переводу, либо закреплена тестами и RFC-0012 как английский контракт; имена команд, подкоманд, флагов и переменных окружения переводить нельзя. **[из файла: `cli/inventory.md` §2.1, §2.3, §2.4, 20.11.2026]**

Man у всех четырёх строится из того же дерева `clap::Command`, что и `--help`. Отдельного «только man» каталога строк нет. Перевод man без согласия авторов на перевод `--help` (или без отдельного, ещё не существующего слоя только для roff) ломал бы тесты, которые пинают английскую справку. **[проверено: генераторы + тесты + inventory §2.1]**

## Общая схема (одинакова у всех четырёх)

1. Пример `apps/<prg>-cli/examples/man-and-completions.rs`, функция `generate(dir)` (у photocraft она не `pub(crate)`, у остальных трёх — `pub(crate)`, чтобы её звали тесты).
2. Аргумент ровно один: каталог вывода. Нет флага языка, нет переменной локали. Лишний или отсутствующий аргумент — usage, код 2. [проверено: `main` во всех четырёх файлах]
3. В каталог пишутся completions пяти оболочек (`clap_complete`) и man (`clap_mangen::generate_to(command(), dir)`). Перед man берут **свежее** `Command`, потому что `clap_complete::generate_to` дописывает синтетическую подкоманду `help`, из которой иначе получились бы лишние страницы вроде `photocraft-cli-help-convert.1`. [проверено: комментарий в каждом примере]
4. Текст страниц — это метаданные того же `clap::Command`, что и для `--help`: doc-комментарии `///` (about / help), атрибуты `#[command]`, `#[arg]`, иногда функции `*_about()` / `*_help()`, которые собирают строку со списком форматов. Имена бинаря и подкоманд заданы латиницей в `#[command(name = …)]` / enum. [проверено: `args.rs` / `lib.rs`]
5. `clap_mangen` 0.3 (у photocraft, cadcraft, soundcraft — `0.3.3` с feature `"env"`; у figcraft — `"0.3"` в `apps/figcraft-cli/Cargo.toml`). Feature `"env"` включает в man переменные окружения из clap, это не локализация. [проверено: Cargo.toml; смысл feature — **догадка** по названию и обычной документации crate, исходник crate на этой машине не разбирался **не проверено**]
6. Вызов `clap_mangen::generate_to` в примерах принимает только `Command` и каталог — параметра языка нет. [проверено: четыре примера]

Что понадобилось бы авторам, общего для всех четырёх (это **не** предложение внедрить сейчас, а перечень отсутствующих частей):

- Явный язык авторов: переводится ли человекочитаемая проза `--help`/man, при том что идентификаторы команд, флагов и `<APP>_*` остаются английскими (**из файла: inventory §2.3, план §4.7**). Сейчас у AniCraft запрет прямой; у этих четырёх справка закреплена RFC-0012 и тестами help/usage. [из файла]
- Либо слой перевода метаданных clap (тогда изменится и `--help`, и сломаются пины), либо отдельный конвейер только для roff, которого нет.
- Генератор, пишущий во второй каталог (например `cli-docs/ru/`) или с аргументом локали.
- Установка в `/usr/share/man/ru/man1/` (Linux/FHS) и, для FreeBSD, в `man/ru/man1/` рядом с нынешним `man/man1/`. Сейчас ни `package.sh`, ни `nfpm.yaml` такого пути не знают: nfpm копирует весь `${STAGE}/usr/share/` как есть. [проверено]
- Решение, ставить ли figcraft man в пакеты вообще (см. ниже): сейчас генератор есть, установка — нет. [проверено: `docs/cli.md`]
