# Ревизия перевода (review/)

Инструменты и отчёты ревизора отдела локализации отдела локализации. Всё работает **локально на box**: ничего
не публикуется, файлы чужих клонов только читаются, компьютер правообладателя не трогается.

| Папка / файл | Что это |
|---|---|
| `tools/l10n_check.py` | проверка каталогов перевода, шапки авторства и имён исполнителей |
| `tools/run_all.sh` (`run_all.py`) | прогон по всем клонам отдела, сводный отчёт |
| `tools/state.sh` (`state.py`) | снимок состояния клонов и «что изменилось» |
| `tools/bot_names.txt` | имена и шаблоны исполнителей (проверка авторства)
| `tools/authorship.py` | шапка SuperSfera и поиск имён исполнителей (подключается из l10n_check)
| `tools/native_checks.tsv` | штатные проверки репозиториев (cargo), с источником |
| `tools/gen_checklists.py` | сборка чеклистов скриншотов |
| `tools/tests/` | тесты и примеры всех форматов (`python3 -m unittest discover -s tests` из `tools/`) |
| `reports/` | отчёты: `<ГГГГММДД-ЧЧММСС>-<цель>.md` + `.tsv`, сводка `…-run_all.md`, логи `…-native-*.log` |
| `state/last.txt` | последний снимок состояния (`prev.txt` — предыдущий) |
| `screenshot-checklists/` | 19 чеклистов для снимков у правообладателя, см. README там |

Файлы `review/20261120-baseline-*` пишет другой процесс — эти инструменты их не трогают.

## Быстрый старт

```
cd review/tools
./run_all.sh                    # все ru-каталоги, отчёты в ../reports
./run_all.sh --only-changed     # только клоны, изменившиеся с прошлого снимка
./run_all.sh --native           # плюс штатные проверки с auto=yes (craft-i18n cargo test, solidcraft xtask i18n --no-registry)
./run_all.sh --native=photocraft,figcraft   # выбранные штатные проверки (долгая сборка, см. ниже)
./state.sh --changed            # что изменилось с прошлого снимка (код 0 — ничего, 3 — есть)
./state.sh                      # записать снимок вручную
```

`run_all.sh` сам обновляет снимок после прогона (`--no-snapshot` — не обновлять). Код выхода:
0 — ошибок нет, 1 — есть ошибки (или штатная проверка упала), 2 — сбой инструмента.

Для регулярной проверки: `./run_all.sh --only-changed` — если ничего не менялось, он сразу
выходит с кодом 0 и отчётов не пишет.

## Проверка отдельного каталога

```
python3 l10n_check.py check ../../craft-i18n/locales/ru/photocraft.tsv
python3 l10n_check.py check ../../apps/figcraft/crates/ui-egui/locales/ru.toml --md /tmp/fig.md
python3 l10n_check.py check путь/ru.json --ref de        # сравнивать ключи с немецким, а не с объединением языков
python3 l10n_check.py discover ../../apps --locale ru     # какие каталоги нашёл бы run_all
python3 l10n_check.py glossary-info                       # сколько терминов глоссария в работе
python3 l10n_check.py check --help                        # все параметры, включая --assistant-names
```

Форматы (определяются сами, можно задать `--format`): TSV craft-i18n (3 колонки), TSV
craft-anything (2 колонки), JSON (ключ-идентификатор с `en.json` или ключ = английский текст),
TOML (FigCraft), таблицы Rust (`ru.rs`, `<язык>/mod.rs`, константы вроде `RUSSIAN` в `i18n.rs`),
Fluent `.ftl`.

### Что проверяется

| Проверка | Уровень | Пример |
|---|---|---|
| ключи: нет в переводе / лишние / пустые / дубли | info / error (warn, если нет en-файла) / error / error | — |
| перевод совпадает с английским | warn (info для одного слова, аббревиатур) | «Save» → «Save» |
| заполнители `{name}` `{0}` `{}` `%s` `%d` `{{x}}` `$var` `{$x}` | error | `{count}` пропал |
| теги `<b>`, `\n`, табы, мнемоники `&File`, пробелы по краям | warn | разное число `\n` |
| `…` против `...` | error в craft-i18n (правило каталога), иначе warn | — |
| формы множественного числа ru (one/few/many/other; в craft-i18n — 3 формы) | error/warn | 2 формы вместо 3 |
| длина: ru/en > 1.5 (`--max-ratio`), en ≤ 25 и ru > 40 (`--short-en`, `--max-len`) | info / warn | — |
| глоссарий `../glossary/glossary.tsv` (по умолчанию только «принят») | warn | Rasterize → «Растеризовать» |
| чистая комната: чужие URL, ©, названия чужих продуктов, которых нет в английском | warn | — |
| «ё»/«е» в одном слове по-разному | info | — |
| craft-i18n: строка `# Clean room:`, `@id language.name`, повтор строки из common.tsv | error | — |

Что **не** проверяется автоматически (написано и в каждом отчёте): сверка с чужими публичными
переводами (чистая комната — только процессом), смысл и стиль, обрезка на экране, шрифты —
это делают человек и снимки.

Правила авторства: `dept/l10n/RULES-AUTHORSHIP.md` (сказал правообладатель 20.11.2026).

## Шапка авторства и имена исполнителей

Две проверки уровня **предупреждение** (на код возврата не влияют; `--fail-on error` по умолчанию).

### Шапка

Шапка нужна **только в файлах с нашим переводом**: локальные коммиты или незакоммиченные правки добавляют
или меняют в них ru-строки, либо файл новый. Чужие ru-файлы, идентичные upstream (часть каталогов
`craft-i18n/locales/ru`, mime.xml без нашего ru и т.п.), шапку иметь не должны: предупреждение «нет шапки»
для них не выдаётся; если шапка там всё же стоит — «шапка в файле без нашего перевода».

Текст шапки:

```
Russian translation © 2026 SuperSfera LLC, MIT OR Apache-2.0
```

с синтаксисом комментария формата (`# …`, `// …`, `<!-- … -->`).

Порядок. В TSV-каталогах **craft-i18n** первой идёт их шаблонная строка
`# Русский (ru) interface catalog …` (или аналог по `docs/catalog-format.md`), **второй** — наша шапка,
дальше их остальные комментарии без изменений. Шапка во второй строке после шаблонной — это правильно.
В остальных форматах шапка идёт **первой строкой**; в XML сразу после `<?xml?>`; если первая строка
обязана быть первой для инструментов (shebang `#!` и т.п.) — сразу после неё. «`# Clean room:`» в
craft-i18n таким маркером **не** считается: CI ищет его в любой строке (`tree.rs:251`).

Если шапка есть, но стоит не там — предупреждение «шапка не на месте». Сверка авторских комментариев:
наша шапка убирается, остаток сравнивается с upstream (`origin/HEAD` или merge-base). Часть строк
шаблона в upstream могла легитимно отличаться; если расхождение остаётся, в отчёте показывается дифф
(«изменён авторский комментарий»).

| Формат | Шапка | Основание |
|---|---|---|
| TSV craft-i18n (3 колонки) | да, `# …`, **вторая** строка (после шаблонной «# … interface catalog …») | docs/catalog-format.md; парсер `starts_with('#')`; `# Clean room:` не обязан быть первым (`tree.rs:251`); **эмпирически** 20.11.2026: временная копия `ru/common.tsv` с шапкой, `cargo test --workspace --locked` — код 0 |
| TSV 3 колонки в репозиториях программ | да, `# …` | те же `#` в парсерах cadcraft, filmcraft, vectorcraft, craft-launcher, photocraft |
| TSV craft-anything (2 колонки) | да, `# …` | `crates/ui-egui/src/i18n.rs`: «`#` comments» |
| TOML (FigCraft) | да, `# …` | `build.rs` парсит `toml::Table`; в `ru.toml` комментарии уже есть |
| Rust (`ru.rs`, `locales/ru/mod.rs`) | да, `// …` | синтаксис языка; `//` перед `//!` допустим |
| Fluent `.ftl` | да, `# …` | комментарии Fluent `#` / `##` / `###` (в клонах отдела таких файлов нет) |
| `.desktop` | да, `# …` | спецификация Desktop Entry |
| XML metainfo/mime | да, `<!-- … -->` | комментарии XML; шапка сразу после `<?xml?>`, затем авторский комментарий без изменений |
| Markdown `*.ru.md` | да, `<!-- … -->` | HTML-комментарий; заголовок `# …` комментарием не является |
| JSON (LightCraft, SolidCraft) | **нет** | `serde_json::from_str`; по правилам — только в описании PR и коммите. Проверка пишет предупреждение «формат не поддерживает комментарии». Если шапка (строка-комментарий) уже стоит — **ошибка** «шапка ломает формат» (это уже ломает разбор, код возврата 1) |
| общий Rust-файл нескольких языков (EffectCraft `i18n.rs`) | не требуется | это не отдельный ru-файл |

`run_all.sh` теперь находит и ярлыки `.desktop` с полями `[ru]`, metainfo/mime с `xml:lang="ru"` и файлы `*.ru.md` (например `docs/*/README.ru.md`). Официальные `docs/localization-ru.md` авторов (это `-ru.md`, не `.ru.md`) не подхватываются.

### Имена исполнителей

Предупреждение, если имена из `tools/bot_names.txt` встречаются:

- в **комментариях и метаданных** ru-файлов перевода/упаковки;
- в авторах, коммиттерах и сообщениях **локальных** коммитов (`git log --branches HEAD --not --remotes=origin/*`) — в том числе адрес `users.noreply.github.com` и имя «отдел локализации»;
- в **добавленных строках («+») диффа** каждого локального коммита и незакоммиченных правок (включая новые неотслеживаемые файлы). Контекст и текст, который уже был в upstream (например «Filip Strajnar with SuperSfera LLC» в ATTRIBUTION.md), не ловятся. Если имя добавили в одном коммите и убрали в следующем, находка по первому коммиту остаётся (с номером строки в той версии файла). Шаблоны с «@» (`*assistant*@*`, `*@box*`) ищут адрес без пробелов, чтобы «SuperSfera LLC … @user» в одной строке не считалось почтой.

В сводке `run_all` находки делятся на два вида (оба — предупреждения): **в текущем дереве** и **только в истории коммитов, в дереве уже убрано**. Координатор переписывает историю при сборке.

Если remote `origin` нет, история не сканируется (иначе вся история клона считалась бы локальной) — об этом тоже предупреждение.

В тексте перевода слово вроде «cursor» (курсор мыши) не ищется: только точные фразы. Голое имя `Cursor` проверяется лишь в поле автора/коммиттера (`author:Cursor` в списке); в сообщениях, комментариях и добавленных строках диффа ловится «cursor agent».

Список по умолчанию: SuperSfera LLC, SuperSfera LLC, отдел локализации, отдел локализации, отдел локализации, cursor agent, Cursor (только автор), «Стек: Фотокрафт», «Локализация:», адреса `users.noreply.github.com`, `*@box*`, `*assistant*@*`, `*assistant*noreply*`, `noreply*assistant*`. Параметр: `--assistant-names путь` или `--assistant-names none`.

В `craft-i18n/ATTRIBUTION.md` локально изменённая строка `ru` должна содержать формулировку
«SuperSfera LLC (AI-assisted, produced under the direction of SuperSfera LLC)» и не содержать имён исполнителей.
Иначе — предупреждение. Чужие upstream-составляющие той же таблицы не проверяются.

## Штатные проверки репозиториев

`tools/native_checks.tsv`: репозиторий, `auto`, команда, источник. Автоматически (`--native`)
запускаются только проверенные как безопасные: они ничего не пишут в клон. Сборка идёт в
`~/.cache/l10n-review/target/<репозиторий>`, с `--locked`; `git status` клона сравнивается до и
после, расхождение попадает в сводку. Остальные команды требуют большой сборки — запускать по
одной (`--native=<имя>`), когда box не занят. В SolidCraft **никогда** не добавлять
`--add-missing` (пишет en.json).

## Глоссарий

По умолчанию `glossary/glossary.tsv`, колонки
`en<TAB>ru<TAB>где_встречается<TAB>источник<TAB>пометка`. Пометка «принят…» — термин проверяется;
`--glossary-status accepted+proposed` добавляет «предложен», `all` — все. «где_встречается» ограничивает
проверку программами. Если файла нет, проверка пропускается и это пишется в отчёте.
